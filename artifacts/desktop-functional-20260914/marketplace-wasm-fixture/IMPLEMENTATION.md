# Signed marketplace WASM tool: implementation proposal

Status: design and executable artifact only. No package installed, no trusted deployment key added, no ROOT changed. This is not native acceptance. The generated signer private key existed only in the build process and was not persisted.

## Execution placement

Use the Python data plane for the first real native **Cloud** conversation. Electron remains the actual user interface; its Cloud session reaches the existing Python agent execution path. The WASM guest executes under the existing Wasmtime Python host, never as Python source or frontend code. The package module declares targets=[python], runtime=wasm, trust=signed and the existing service:tool-set-catalog contribution contract. Keep desktop-sidecar, desktop-renderer, web, rust-server module projection unchanged: each validates the whole protocol but only loads modules targeting itself. Add real cross-target projection tests so ignored Python modules cannot accidentally become missing native catalog errors. This first implementation does not establish Local-mode plugin execution; that needs a separate Rust-sidecar adapter later.

## Work packages and dependent checks

1. Verified external module admission. Extend the production LoaderV2 path with a generation-local catalog derived exclusively from InstalledVerifiedBundleLoaderV2 / ScopedInstalledBundleLoaderV2 verified archives and the exact requested distribution. Keep generated builtins immutable. Reject external module/plugin identifiers colliding with builtins, duplicate definitions, changed versions/digests, unknown runtime/ABI, unmatched target, unapproved services/permissions and missing artifact bytes. Do not allow a renderer-supplied catalog or a generic dynamic Python import. Current runtime.py, runtime_contracts.py, verified_execution_artifacts.py and artifacts.py are the seams. A bounded WasmVerifiedArtifactResolver consumes the exact archive artifact matching target+digest; it never resolves arbitrary filesystem paths or URLs. Do not make the absent generated catalog check optional for builtin modules.

2. Real WASM definition factory. Dispatch only the admitted runtime=wasm, entrypoint=score ABI into the existing WasmToolHost. The factory produces a normal PluginDefinitionV2 and registers a ToolSetV2 contribution with the required catalog via ContextV2. No arbitrary service provider or config-defined Python callback is supported. Verify export type score(i32)->i32 and zero imports before activation. Preserve actual archive bytes and digest attribution in the definition. Python WasmToolHost currently has fuel but lacks the Rust host's memory/wall-clock protections: add memory/store limits and interruptible execution before accepting external packages. Execute blocking Wasmtime outside the asyncio event loop. Define ABI input consistently: the current Python adapter passes UTF-8 input JSON byte length; the marker ignores it. Do not claim Python/Rust input parity, as Rust currently uses text character length or len.

3. Agent tool integration. Use tool_set.py register_tools and agent_operation_tool_contributions.py leased ToolDefinition wrappers. Give the tool a namespaced name, fixed JSON input/result schemas, explicit Pure side-effect metadata and immutable package/module/digest attribution. A factory supplies the actual operation's tenant/project/session and enforces the existing approved permission grant before exposing or invoking tools. Signed trust alone does not grant all tenants access. A revoked/uninstalled package must be denied on a new invocation even if an old generation lease still exists; integrate governance revision/permission revalidation in that invocation boundary. Do not rely solely on eventually retired registration. Preserve normal Act/Observe and structured tool result events.

4. Lifecycle and publication. Existing official marketplace install is a ROOT desired mutation; do not describe it as scoped installation. Retain install/approve/revoke/uninstall authorization and immutable package verification. A default-disabled entry can be installed and later enabled through the existing authorized desired/profile layer mechanism; review exact supported scoped source ownership before exposing that as a product switch. Uninstall and revoke must remove visibility, reject new calls and retire generation-owned resources; in-flight bounded pure work may finish under its captured lease, but cannot acquire new capabilities. Reinstall a revoked version remains forbidden. Avoid adding a test-only installed-state bypass.

5. Real package transport. The fixture contains actual WASM bytes in a schema-valid, Ed25519-signed mspkg. Publish it only later to an operator-approved loopback OCI registry, serving the real OCI manifest and ZIP layer, using OciPluginArtifactClient. Construct OCI manifest with schemaVersion=2, mediaType=application/vnd.oci.image.manifest.v1+json, artifactType=application/vnd.memstack.plugin.v2 and one application/vnd.memstack.plugin.bundle.v2+zip layer. Compute both digests from actual bytes. The official install request carries package bundle_id/version, publisher, QA tenant_id, registry/repository/manifest_sha256, archive artifact_sha256, exact bundle.json, public PEM/signature, provenance, tools.execute approval and honestly completed security scan/tenant approval. The fixture key is not trusted by the deployment; trust configuration and package publication require their own reviewed dev setup. No FakeArtifactClient.

6. Native acceptance after the above tests. Record baseline ROOT content and isolate the QA tenant/session. Official install must return success and all required data planes must ACK. Select the tool in a real Electron Cloud conversation and obtain score=20260914 from an actual model tool call, with correlated Act/Observe and tool attribution. Disable it, verify absent/denied; re-enable, call; revoke, verify cached and fresh invocation denial; uninstall, verify catalog/desired removal and no callable tool after native restart. Retain package and event IDs, never secret values. This is the first point at which native marketplace execution can be marked passed.

## Failure tests

Already executable with build_and_verify.py: real signed archive verification; actual Wasmtime score=20260914; tampered artifact rejected; untrusted signer rejected; missing permission rejected; runaway guest traps on fuel; real current production LoaderV2 rejects the new module with missing_target_catalog. That last test must turn green only after production admission/factory work, using real archive verification and loader, not a replacement loader.

Required regression tests: same-size byte tampering; wrong signature; omitted target artifact; built-in namespace collision; unknown ABI and export type; forbidden imports/WASI; fuel/memory/time exhaustion without blocking another request; wrong tenant/project; contributor service escalation; disabled entry; duplicate tool names; revocation after lease acquisition; uninstall during invocation; stale archive/reference; reload failure preserves last-good generation without exposing the failed tool; cross-target staging and ACK; actual local OCI fetch through OciPluginArtifactClient.

## Delivery order

A and B can be independent: (A) archive-backed catalog/resolver admission with failure tests; (B) WASM factory, quotas and ToolSet contract tests. Then (C) integrate production startup/scoped loaders and operation permission/lifecycle boundaries; (D) real OCI HTTP integration and official install lifecycle tests; (E) coordinated native Cloud acceptance. Keep native Rust execution as a separately scoped follow-up, not implied by Cloud success.
